'@cloudflare/workers-oauth-provider': major

Add the role-based `OAuthAuthorizationServer` API. It takes `resources`, the canonical identifiers of every protected resource it issues tokens for, so the registry is fixed at construction and `defaultResource`, `legacyGrantResource`, and every handle are validated before the first request. `resource(uri)` returns a handle whose `validateToken(token, env)` is pinned to that resource, suitable for a private Service Binding, and whose `protect()` hosts it in the same Worker. `protectResource()` hosts a declared resource and returns its independently routable fetch surface. Authorization server metadata advertises the registry through RFC 9728 `protected_resources`.

Add `createOAuthResourceServer()` for a separately deployed protected-resource Worker. It publishes that resource's RFC 9728 metadata, returns Bearer challenges, accepts an application-supplied token-validation callback, checks the returned audience and expiry, and exposes validated application properties to the protected handler. The package does not add a public introspection or JWT endpoint.

Bind every new grant and access token to exactly one registered canonical resource. A multi-resource authorization request must select exactly one resource unless `defaultResource` supplies a deliberate compatibility default. Code exchange and refresh inherit the resource stored on the grant and reject attempts to retarget it. Grants for the same user and client replace only grants for the same resource, so authorizing one MCP server does not revoke another server's grant.

Stored state written by 0.x keeps working. An authorization server with one registered resource uses it when a client omits `resource` and as the migration destination for a pre-resource grant or access token; multi-resource deployments configure `legacyGrantResource` for that. Access tokens issued before resource binding keep working at that destination until they expire, a stored array audience resolves to the registered resource it contains, and refresh binds the grant. A grant that cannot be bound to any registered resource fails its refresh with `invalid_grant`, which conformant clients answer with a new authorization.

Require canonical `resourceMetadata.resource` values for hosted protected resources, and reject at construction any `apiRoute` or `apiHandlers` key the resource does not cover, since a token could never validate there. Plain `http` is accepted for resources, issuers, and endpoint URLs only on loopback hosts (`localhost`, `127.0.0.0/8`, `::1`), so `wrangler dev` works on http://localhost; any other host must use `https`. Remove `resourceMatchOriginOnly`; a configuration that still sets it fails at construction. Explicit resource values tolerate only ASCII case differences in the URI scheme and host. Token exchange, protected API access, external token resolvers, and standalone resource-server callbacks all fail closed on an audience mismatch.

Challenges advertise the canonical `resource_metadata` on the canonical resource and its path-boundary descendants (RFC 9728 §5.1). Discovery documents answer HEAD, send `Allow: GET, HEAD, OPTIONS`, answer OPTIONS across the protected-resource metadata namespace, and tolerate a query string on the authorization server metadata URL. The combined `OAuthProvider` keeps its 0.x endpoint matching; origin gating and static-query rules apply only to `OAuthAuthorizationServer`.

The token endpoint enforces each client's registered `grant_types` with `unauthorized_client`; `refresh_token` is implied by `authorization_code`, and token exchange must be registered explicitly. Token exchange is bound to the client the grant was issued to unless `tokenExchangeCallback` returns `allowCrossClientExchange: true`; the callback receives `subjectClientId`. Subject-token failures return `invalid_request` per RFC 8693 §2.2.2.

Public type changes: `resourceMetadata` and `resourceMetadata.resource` are required on `OAuthProviderOptions`; `resources` is required on `OAuthAuthorizationServerOptions`; `registerResource()` and the three-argument `validateToken()` are removed in favor of `resource(uri)`; `ResolveExternalTokenResult.audience` is required; `ExchangeTokenOptions.aud`, `AuthRequest.resource`, and `TokenExchangeCallbackOptions.resource` are single strings; `TokenExchangeCallbackOptions.subjectClientId` and `TokenExchangeCallbackResult.allowCrossClientExchange` are added.
